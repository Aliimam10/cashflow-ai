# CashFlow AI v1.0.0 release candidate

Release date target: 2026-09-05  
Distribution: local source checkout and local Docker image  
Python: 3.12  
Persistence: local SQLite

Version 1 completes the planned local single-user workflow from review-gated bank
statement extraction through verified cash-flow analytics, cautious forecasts,
budgets, goals, scenarios, and unusual-activity review. It does not connect to a bank,
move money, deploy a remote service, or replace professional financial advice.

## Highlights

- CSV statements can be previewed, mapped, confirmed, and persisted with complete
  raw-row lineage and atomic failure behavior.
- Digital and scanned PDFs can be extracted and corrected locally, with confidence,
  original evidence, and balance reconciliation retained through in-memory approval.
- Transfers, refunds, reimbursements, withdrawals, categories, and unresolved rows
  remain financially distinct and explicitly reviewable.
- Missing coverage remains unknown across analytics, recurrence, model training,
  forecasts, and planning.
- Forecasting uses chronological evaluation, five simple baselines, conservative
  model selection, empirical uncertainty, and visible stale-data/fallback warnings.
- FastAPI and Streamlit stay on loopback; Docker adds local Tesseract and private
  persistent volumes without adding remote infrastructure.

See the [user guide](../user_guide.md), [architecture diagrams](../diagrams.md),
[evaluation record](../evaluation.md), and [privacy guide](../privacy.md).

## Reproducible release evidence

The complete local gate must pass with 100% statement and branch coverage:

```bash
make format
make check
make pre-commit
make check-import
```

Synthetic manual demonstrations recorded during release preparation showed:

- the API persisted two fictional CSV rows, returned role-aware income `1000.00`,
  expenses `400.00`, and net cash flow `600.00`, omitted raw payloads, and removed
  its temporary database;
- the primary forecast demo selected histogram gradient boosting on its designed
  nonlinear fixture with final MAE `3.18` versus `75.00` for the best baseline;
- a flat forecast fixture rejected the advanced candidate and executed the
  historical-mean baseline with both final MAEs at `0.00`;
- the 30-day path demo reported an expected fictional balance of `£929.48`, a
  `£907.48–£947.45` likely range, and empirical coverage `1.00` on its small
  synthetic holdout; and
- anomaly review used rules plus the gated model with sufficient history, but used
  rules only and emitted insufficient-coverage/history warnings in sparse mode.

These results verify deterministic behavior and safeguards on purpose-built
fictional data. They are not estimates of categorisation, forecast, interval, or
anomaly accuracy on real financial data. The detailed interpretation is in
[`evaluation.md`](../evaluation.md).

## Breaking and migration notes

This is the first stable package version, so there is no supported earlier public API
to migrate. Existing development databases must be backed up locally and upgraded
with:

```bash
make db-upgrade
```

Do not use `make db-downgrade` on financial data: it removes application tables. The
container performs only the forward upgrade automatically before starting its local
API. The project does not migrate a SQLite database to PostgreSQL or upload it.

## Known limitations

- Only GBP current/checking and savings accounts are accepted.
- PDF extraction is layout-dependent, and PDF approval is not persisted in Version 1.
- No bank API, transaction sync, credit-card account, debt planner, investment
  account, tax calculation, multi-user isolation, authentication, TLS, backup
  automation, accessibility certification, or remote deployment is included.
- Categorisation learns only from explicit corrections and may have insufficient
  examples for leakage-safe holdouts.
- Forecast performance can change, recursive horizon errors can compound, and
  empirical ranges do not guarantee future balances.
- Isolation Forest scores are uncalibrated review rankings, not fraud probabilities.
- The Docker image is locally built and is not published to a registry.
